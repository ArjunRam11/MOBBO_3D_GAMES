================================================================================
                    CoP SCALING VISUAL ARCHITECTURE
================================================================================

DATA FLOW DIAGRAM:
==================

    PYTHON (main.py)
         ↓
    Detects board pose
    Extracts layout: "1x2" or "2x1"
         ↓
    Sends UDP packet with:
    - raw_x, raw_y, raw_z (global CoP)
    - board_layout info
         ↓
    GODOT (global_script.gd)
         ↓
    handle_cop_data_safe()
         ├─ Receives raw_x, raw_y, raw_z
         ├─ Normalizes using board layout ranges
         │   - cop_x_min, cop_x_max
         │   - cop_y_min, cop_y_max
         ├─ Converts to screen coordinates
         │   - net_x, net_y, net_z
         └─ Stores in output vectors
            - network_position (2D games)
            - network_position3D (3D games)
         ↓
    handle_board_pose_data_safe()
         └─ set_scaling_for_layout()
            (Updates cop_x_min/max, cop_y_min/max)
         ↓
    GAME SCRIPTS
         ├─ Flappy Bird (pilot.gd)
         │  position.lerp(network_position3D, 0.8)
         ├─ Fruit Catcher (paddle.gd)
         │  position.x = lerp(position.x, network_position.x, 0.8)
         └─ Jumpify (2Dplayer.gd)
            position.lerp(network_position3D, 1.0)
         ↓
    GAME OBJECTS MOVE ✓

           means normalized_x = 1.0 - normalized_x


================================================================================
                    NORMALIZATION FORMULA BY LAYOUT
================================================================================

GENERIC FORMULA:
════════════════

  actual_min = min(cop_x_min, cop_x_max)
  actual_max = max(cop_x_min, cop_x_max)

  normalized = (raw_value - actual_min) / (actual_max - actual_min)
  normalized = clamp(normalized, 0.0, 1.0)

  # Handle reversed axis (2x1 layout)
  if cop_x_min > cop_x_max:
    normalized = 1.0 - normalized

  screen_value = screen_min + (normalized * (screen_max - screen_min))


EXAMPLE 1x2 LAYOUT:
═══════════════════

  Given:
    raw_x = -0.30 (middle position)
    cop_x_min = -0.90
    cop_x_max = +0.30
    MIN_X = 100
    MAX_X = 1820

  Step 1: Find actual range
    actual_min = -0.90
    actual_max = +0.30
    range = 1.20

  Step 2: Normalize
    normalized = (-0.30 - (-0.90)) / 1.20
    normalized = 0.60 / 1.20
    normalized = 0.50  (middle of screen)

  Step 3: Check if reversed
    cop_x_min (-0.90) NOT > cop_x_max (0.30)
    So NO inversion

  Step 4: Map to screen
    screen_x = 100 + (0.50 * (1820 - 100))
    screen_x = 100 + (0.50 * 1720)
    screen_x = 100 + 860
    screen_x = 960  ✓ (center of screen)


EXAMPLE 2x1 LAYOUT:
═══════════════════

  Given:
    raw_x = 0.0 (middle position)
    cop_x_min = +0.30
    cop_x_max = -0.30
    MIN_X = 100
    MAX_X = 1820

  Step 1: Find actual range
    actual_min = -0.30  (min of 0.30 and -0.30)
    actual_max = +0.30  (max of 0.30 and -0.30)
    range = 0.60

  Step 2: Normalize
    normalized = (0.0 - (-0.30)) / 0.60
    normalized = 0.30 / 0.60
    normalized = 0.50  (middle)

  Step 3: Check if reversed ⚠️
    cop_x_min (0.30) IS > cop_x_max (-0.30)
    INVERT: normalized = 1.0 - 0.50 = 0.50
    (stays same in this case, but formula reverses motion)

  Step 4: Map to screen
    screen_x = 100 + (0.50 * (1820 - 100))
    screen_x = 960  ✓ (center of screen)


MOTION EXAMPLE 2x1 RIGHT EDGE:
══════════════════════════════

  Given: raw_x = 0.30 (right side of 2x1 board)

  Normalize:
    normalized = (0.30 - (-0.30)) / 0.60 = 1.0

  Reverse (because 2x1):
    normalized = 1.0 - 1.0 = 0.0

  Screen:
    screen_x = 100 + (0.0 * 1720) = 100  ← LEFT EDGE

  ✓ Correctly maps right edge of board to left edge of screen!


================================================================================
                       GAME RESPONSE CHARACTERISTICS
================================================================================

FLAPPY BIRD (pilot.gd):
═══════════════════════

Input:  network_position3D.y (vertical CoP position)
Output: position.y (bird height)
Movement: position.lerp(network_position, 0.8)

Behavior:
  • Smooth movement (0.8 lerp = 80% influence per frame)
  • Controlled by Y axis (forward/backward CoP)
  • X position FIXED at 100
  • Good for vertical movement tasks

Response Time: ~50ms (smooth, natural)


FRUIT CATCHER (paddle.gd):
══════════════════════════

Input:  network_position.x (horizontal CoP position)
Output: position.x (paddle left/right)
Movement: position.x = lerp(position.x, adjusted_x, 0.8)

Behavior:
  • Smooth horizontal movement
  • Controlled by X axis (left/right CoP)
  • Y position FIXED at 615
  • Applies center offset: Vector2(120, 200)
  • Movement threshold: 2.0 pixels minimum

Response Time: ~50ms (smooth, with threshold)


JUMPIFY (2Dplayer.gd):
══════════════════════

Input:  network_position3D (full position)
Output: position (player location)
Movement: position.lerp(network_position, movement_smoothing)  # 1.0

Behavior:
  • DIRECT movement (1.0 lerp = 100% new position per frame)
  • Controlled by both X and Y axes
  • Full 2D movement in game space
  • Maps back to game coordinates: game_x = (position.x - X_OFFSET) / SCALER
  • Logs position to CSV file

Response Time: Immediate (no smoothing)

TROUBLESHOOTING:
════════════════

Symptom: Game object doesn't move
  → Check: Is raw_x/y/z received? Print in console
  → Check: Is set_scaling_for_layout() called?
  → Check: Are cop_x_min/max/y_min/max values reasonable?
  → Fix: Manually call set_scaling_for_layout("2x1") to test

Symptom: Movement is inverted (left becomes right)
  → This is EXPECTED for 2x1 layout (X is reversed)
  → Verify: cop_x_min (0.30) > cop_x_max (-0.30)
  → Verify: normalized = 1.0 - normalized is applied
  → For 1x2: movement should not be inverted

Symptom: Movement is jerky or unresponsive
  → Check: Movement smoothing value (lerp factor)
  → For smooth: use 0.8 (current)
  → For responsive: use 1.0 (Jumpify)
  → Adjust: change 0.8 to 0.5 for more smoothing

Symptom: Game object goes off-screen
  → Check: Are MIN_X, MAX_X, MIN_Y, MAX_Y set correctly?
  → Check: Is clampf() applied to normalized values (0.0-1.0)?
  → Check: Do your scaling ranges match board dimensions?
  → Fix: Add bounds checking in game scripts
